🏃 Training & Optimization

How a network actually learns: the training loop, gradient descent variants, momentum & Adam, learning rates, and the tricks that stop it from memorizing instead of learning.

← Back to Learning Path
Big picture: Training is a loop. Show the model some data, measure how wrong it is (the loss), compute which direction reduces the error (the gradient), and take a small step that way. Do this millions of times — that's optimization. The rest of this page is about doing that loop well.

1. The Training Loop — epochs & batches

Learning doesn't happen in one shot. The model sees the data over and over, in small chunks.

The three words you need

TermMeaning
BatchA small group of training examples processed together before one weight update.
IterationOne weight update (one batch processed: forward → loss → backward → update).
EpochOne full pass over the entire training set (many batches / iterations).

Example: 10,000 examples with a batch size of 100 → 100 iterations make 1 epoch. Train for 20 epochs → 2,000 total weight updates.

Why mini-batches? Using the whole dataset per update is slow and memory-hungry; using one example at a time is noisy. A mini-batch (e.g. 32–256 examples) is the sweet spot: fast, stable, and it makes good use of parallel hardware (GPUs).

The loop, step by step

  1. Sample a batch of training data.
  2. Forward pass: compute predictions.
  3. Loss: measure how wrong the predictions are.
  4. Backward pass: compute the gradient (∂loss/∂weight) for every parameter.
  5. Update: nudge each weight downhill: w = w − lr × gradient.
  6. Repeat for every batch, for many epochs.

2. Gradient Descent Variants

All three do the same update rule — they differ only in how much data they look at per step.

The one update rule they share

w = w − η · ∂L/∂w

Here η (eta) is the learning rate — the step size. The gradient ∂L/∂w points uphill, so we subtract it to go downhill toward lower loss.

VariantData per updateProsCons
Batch GD Entire dataset Smooth, accurate gradient Slow; huge memory; one update per epoch
SGD (stochastic) 1 example Fast updates; noise can escape bad spots Very noisy path; unstable
Mini-batch A small batch (e.g. 32–256) Best of both; GPU-friendly Batch size is another knob to tune
In practice: "SGD" in modern frameworks almost always means mini-batch gradient descent. It's the default workhorse of deep learning.

3. Momentum & Adam

Plain gradient descent can be slow and jittery. Optimizers add "memory" to smarten each step.

Momentum — a rolling ball

Instead of stepping purely on the current gradient, momentum keeps a running average of past gradients (a velocity). Like a ball rolling downhill, it builds speed in consistent directions and smooths out the back-and-forth wobble across narrow valleys.

v = β · v + (1 − β) · ∂L/∂w  →  w = w − η · v
Intuition: if the gradient keeps pointing the same way, momentum accelerates (faster convergence). If it flip-flops, the averaging cancels the noise out.

Adam — the popular default

Adam (Adaptive Moment estimation) combines two ideas:

  • Momentum — a running average of the gradient (the "1st moment").
  • Adaptive step size — a running average of the gradient squared (the "2nd moment"), used to give each weight its own effective learning rate.

Weights whose gradients are large and noisy take smaller steps; weights with small, steady gradients take larger steps. This "auto-tuning" is why Adam works well out of the box.

Rule of thumb: start with Adam (learning rate around 0.001) — it's forgiving and converges fast. Well-tuned SGD + momentum can generalize slightly better and is common for training large vision models.

4. Learning Rate & Decay

The single most important knob. It controls how big each downhill step is.

Too high, too low, just right

Learning rateWhat happens
Too highSteps overshoot the minimum — loss bounces around or blows up to NaN.
Too lowSteps are tiny — training crawls and may get stuck before reaching a good minimum.
Just rightLoss drops quickly and steadily, then settles.

Learning-rate decay (scheduling)

A big step size is great early (make fast progress) but bad late (you overshoot the minimum). Decay starts the learning rate high and shrinks it over time so the model settles gently into a good minimum.

  • Step decay — multiply the rate by, say, 0.1 every few epochs.
  • Exponential decay — ηt = η0 · e−kt.
  • Cosine decay — smoothly anneal down following a cosine curve.
  • Warmup — ramp up for the first few steps, then decay (common for transformers).

5. Overfitting vs Underfitting

The central tension of machine learning: learn the pattern, not the noise.

Two ways to fail

 UnderfittingOverfitting
SymptomHigh error on both train & validationLow train error, high validation error
CauseModel too simple / trained too littleModel too complex / memorized the training data
FixBigger model, more features, train longerRegularization, more data, simpler model, early stopping
The tell-tale sign: when validation loss starts rising while training loss keeps falling, the model has stopped learning the pattern and started memorizing. That crossover is exactly where early stopping saves the best model.

6. Regularization — fighting overfitting

Techniques that discourage the model from memorizing, so it generalizes to new data.

L2 regularization (weight decay)

Add a penalty for large weights to the loss. The model is nudged to keep weights small, producing a simpler, smoother function that's less likely to fit noise.

Ltotal = Ldata + λ · Σ w²

The strength λ (lambda) controls how hard we push weights toward zero. This is called weight decay because each update shrinks the weights a little.

Dropout

During training, randomly "drop" (set to zero) a fraction of neurons on each forward pass. The network can't rely on any single neuron, so it learns redundant, robust features. At test time all neurons are active (dropout is turned off).

Intuition: it's like training a huge ensemble of slightly different networks and averaging them — for almost no extra cost. Typical drop rates: 0.2–0.5.

Early stopping

Watch the validation loss each epoch. When it stops improving (and starts rising), stop training and keep the weights from the best epoch. Cheap, effective, and directly targets the overfitting crossover shown in the graph above.

TechniqueHow it fights overfitting
L2 / weight decayPenalizes large weights → simpler function
DropoutForces redundancy → no over-reliance on single neurons
Early stoppingStops before the model memorizes noise
More data / augmentationHarder to memorize a bigger, varied dataset

7. Train / Validation / Test Split

You can't trust a model tested on data it studied. Keep some data hidden.

The three sets

SetUsed forTouches weights?
Training (~70–80%)Computing gradients & updating weightsYes
Validation (~10–15%)Tuning hyperparameters, early stopping, model choiceNo (indirectly guides choices)
Test (~10–15%)Final, one-time estimate of real-world performanceNo (never seen until the end)
Golden rule: the test set is opened once, at the very end. If you tune against it, you're back to overfitting — just to the test set this time. The validation set is your safe playground for decisions during training.

8. A Full Training Loop in Code

Mini-batch gradient descent with L2 & early stopping

A tiny linear-regression trainer that shows every concept on this page in one loop: batching, the gradient-descent update, weight decay, and early stopping on a validation set.

import numpy as np
rng = np.random.default_rng(0)

# --- Toy data: y = 3x + 2 + noise ---
X = rng.uniform(-1, 1, size=(400, 1))
y = 3 * X[:, 0] + 2 + rng.normal(0, 0.1, size=400)

# train / val / test split (70 / 15 / 15)
n = len(X)
tr, va = int(0.70 * n), int(0.85 * n)
Xtr, Xva, Xte = X[:tr], X[tr:va], X[va:]
ytr, yva, yte = y[:tr], y[tr:va], y[va:]

# --- Parameters to learn ---
w, b = 0.0, 0.0
lr        = 0.1      # learning rate (eta)
lam       = 1e-3     # L2 / weight-decay strength (lambda)
batch     = 32       # mini-batch size
epochs    = 200
patience  = 10       # early-stopping patience

def mse(Xs, ys):
    pred = w * Xs[:, 0] + b
    return np.mean((pred - ys) ** 2)

best_val, best_wb, wait = float("inf"), (w, b), 0

for epoch in range(epochs):
    idx = rng.permutation(len(Xtr))          # shuffle each epoch
    for start in range(0, len(Xtr), batch):  # iterate over mini-batches
        bi = idx[start:start + batch]
        xb, yb = Xtr[bi, 0], ytr[bi]

        # forward + gradients of MSE  (mean over the batch)
        pred  = w * xb + b
        error = pred - yb
        grad_w = 2 * np.mean(error * xb) + 2 * lam * w   # + L2 term
        grad_b = 2 * np.mean(error)

        # gradient-descent update
        w -= lr * grad_w
        b -= lr * grad_b

    # --- early stopping on validation loss ---
    v = mse(Xva, yva)
    if v < best_val - 1e-6:
        best_val, best_wb, wait = v, (w, b), 0
    else:
        wait += 1
        if wait >= patience:
            print(f"early stop at epoch {epoch}")
            break

w, b = best_wb                        # restore best weights
print(f"learned:  y = {w:.3f}x + {b:.3f}   (target 3x + 2)")
print(f"test MSE: {mse(Xte, yte):.4f}")
That's the whole game. Swap the linear model for a neural network and the hand-written gradients for backpropagation, and this exact loop — batches, an optimizer, a learning rate, regularization, and early stopping on validation — trains every deep model.

Quick recap

  • Epoch / batch — one full pass vs one chunk of data per update
  • SGD / mini-batch — how much data each step looks at
  • Momentum / Adam — smarter steps using gradient history
  • Learning rate — step size; decay it as training settles
  • Regularization — L2, dropout, early stopping fight overfitting
  • Data split — train updates, validation guides, test judges once
