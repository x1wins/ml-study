🔁 RNNs & LSTMs: Networks with Memory

How neural networks handle sequences — hidden state, recurrence, the vanishing-gradient problem, and the gates that gave machines long-term memory.

Big picture: A plain neural network sees each input in isolation. But language and time series have order — "dog bites man" ≠ "man bites dog". A recurrent network carries a hidden state from one step to the next, so it remembers what it just saw. LSTMs add gates to remember things over long spans.

1. Sequential Data — why order matters

Some data only makes sense as a sequence: each item depends on the ones before it.

What counts as sequential data?

  • Text — a sentence is a sequence of words/characters; meaning depends on order
  • Time series — stock prices, weather, sensor readings over time
  • Audio — speech is a stream of sound samples
  • Video — an ordered sequence of frames

A regular feed-forward network takes a fixed-size input and treats every example independently. It has no notion of "before" and "after". To model sequences we need something that can carry information forward in time.

Why it matters: To predict the next word in "the sky is ___", the model must remember the earlier words. Memory of the past is the whole point of recurrent networks.

2. The Hidden State & Recurrence

One small loop turns a plain network into a memory machine.

The recurrence idea

An RNN processes one element at a time. At each step t it combines the current input xt with the previous hidden state ht−1 to produce a new hidden state ht. That hidden state is the network's memory — a running summary of everything seen so far.

ht = tanh( Wx · xt + Wh · ht−1 + b )

The same weights Wx, Wh are reused at every time step — this weight sharing is why an RNN can handle sequences of any length with a fixed number of parameters.

Key idea: the loop — feeding the output hidden state back in as an input for the next step — is what makes the network "recurrent". Everything else is a normal neuron.

A tiny hidden-state loop in code

import numpy as np

def rnn_step(x_t, h_prev, Wx, Wh, b):
    # combine current input with previous memory, squash with tanh
    return np.tanh(Wx @ x_t + Wh @ h_prev + b)

# tiny example: 3-dim input, 4-dim hidden state
np.random.seed(0)
Wx = np.random.randn(4, 3) * 0.1   # input  -> hidden
Wh = np.random.randn(4, 4) * 0.1   # hidden -> hidden
b  = np.zeros(4)

sequence = [np.random.randn(3) for _ in range(5)]  # 5 time steps
h = np.zeros(4)                                     # start with empty memory

for t, x_t in enumerate(sequence):
    h = rnn_step(x_t, h, Wx, Wh, b)   # memory updates every step
    print(f"step {t}: hidden state = {np.round(h, 3)}")

# h now summarizes the whole sequence

Notice how h is threaded from one step into the next — that single line is the entire secret of recurrence.

3. Unrolling Through Time

The loop is really the same cell applied again and again — drawing it out reveals the structure.

One cell, many steps

The recurrent loop is hard to reason about, so we unroll it: draw one copy of the cell for each time step, with the hidden state flowing left to right. It looks like a deep network, but every copy shares the same weights.

Because the unrolled network is deep (one layer per time step), we train it with Backpropagation Through Time (BPTT) — ordinary backprop applied to the unrolled graph, summing gradients across all the shared copies.

4. The Vanishing / Exploding Gradient Problem

The reason plain RNNs forget: gradients shrink (or blow up) as they travel back through many steps.

Why long sequences break plain RNNs

During BPTT the gradient is multiplied by the recurrent weight (and the tanh slope) once for every time step it travels back. Multiplying many numbers together has two failure modes:

  • Vanishing: if the factors are < 1, the product shrinks toward 0. Early steps get almost no gradient → the network can't learn long-range dependencies.
  • Exploding: if the factors are > 1, the product grows huge → unstable, wildly swinging weights (often NaN).
gradient ∝ (Wh)T · … · (Wh)   over T steps → 0 or ∞
Concrete symptom: a plain RNN reading "I grew up in France … [50 words] … so I speak fluent ___" struggles to connect "France" to "French" because the gradient linking them has vanished. Exploding gradients are usually patched with gradient clipping; vanishing gradients need a structural fix — the LSTM.

5. LSTMs — Gates Fix Long-Term Memory

Long Short-Term Memory cells add a protected "conveyor belt" of memory controlled by gates.

The cell state and the three gates

An LSTM adds a second memory track, the cell state Ct, that flows straight through the sequence with only minor, gated edits. Because information can travel along it almost unchanged, gradients survive over long spans. Three gates (each a sigmoid that outputs 0–1, i.e. "how much to let through") control it:

GateQuestion it answersEffect
Forget ftWhat should I erase from memory?Multiplies old cell state (0 = forget, 1 = keep)
Input itWhat new info should I store?Scales the candidate update added to the cell state
Output otWhat should I reveal now?Decides how much of the cell state becomes the hidden state
Ct = ft · Ct−1 + it · C̃t    ht = ot · tanh(Ct)
Why gates solve vanishing gradients: the cell state is updated by addition (not repeated multiplication by a weight matrix). When the forget gate stays near 1, gradients flow back across the belt almost unchanged — so the network can link events dozens or hundreds of steps apart.

6. GRUs — the lightweight cousin

Same idea, fewer parts

The Gated Recurrent Unit (GRU) is a simplified LSTM. It merges the cell state and hidden state into one, and uses just two gates:

  • Update gate — how much of the old memory to keep vs. overwrite (does the job of forget + input combined)
  • Reset gate — how much past memory to ignore when forming the new candidate

With fewer parameters, GRUs train faster and often match LSTM accuracy on smaller datasets.

Rule of thumb: try a GRU first (cheaper); reach for an LSTM when you need to model the longest, most complex dependencies. In modern practice, both are increasingly replaced by Transformers.

7. Why This Leads to Transformers

The remaining limits of recurrence

LSTMs and GRUs largely tamed the vanishing-gradient problem, but two structural limits remained:

LimitationWhat it means
Sequential by natureStep t needs the result of step t−1, so computation can't be parallelized across the sequence — slow to train on modern GPUs.
Long-range still fadesInformation is squeezed through one hidden state passed step by step; very distant tokens still influence each other only weakly.

The 2017 Transformer replaced recurrence with attention: instead of passing memory step by step, every position looks directly at every other position in one shot. That removes the sequential bottleneck (fully parallel) and connects distant tokens with a short path.

The bridge: RNNs taught us how to model sequences and carry memory; their limits — no parallelism, fading long-range signal — are exactly what attention was designed to fix. That is the story of the next page, Transformers.

Quick recap

  • Sequential data — order matters (text, time series, audio)
  • Hidden state — a running memory passed from step to step
  • Recurrence — the same cell + shared weights applied at every step
  • Vanishing gradient — why plain RNNs forget long-range info
  • LSTM gates — forget / input / output protect a long-term cell state
  • GRU — a lighter, 2-gate alternative
  • Transformers — attention fixes recurrence's parallelism & range limits
