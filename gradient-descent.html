📉 Gradients & Gradient Descent

The single algorithm behind almost all learning: follow the slope downhill to make the loss smaller, one small step at a time.

← Back to Learning Path
Big picture: Training a model means finding the numbers (weights) that make the error smallest. Gradient descent does this by repeatedly asking "which way is downhill?" (the gradient) and taking a small step that way. That's how nearly every model — from linear regression to giant neural networks — actually learns.

1. Recap: the derivative is a slope

Everything here builds on one idea: a derivative tells you which way — and how steeply — a function is heading.

Slope in one variable

For a single-variable function f(x), the derivative f′(x) (also written df/dx) is the slope at a point: how fast the output changes as you nudge x. A positive slope means the function is going up as x increases; a negative slope means it is going down.

f(x) = x²  →  f′(x) = 2x

So at x = 10 the slope is 2 · 10 = 20 (steeply uphill), and at x = 0 the slope is 0 (flat — the bottom of the bowl).

Need a refresher? See Derivatives for the full story on slopes, rates of change, and how to differentiate. Gradient descent is derivatives put to work.

2. The gradient ∇f — steepest increase

Real models have thousands or millions of weights. The gradient generalizes "slope" to many dimensions.

A gradient is a vector of partial derivatives

When a function has several inputs, we take the derivative with respect to each one separately — a partial derivative, written with ∂. Stack them into a vector and you get the gradient, written ∇f ("nabla f" or "grad f").

∇f = [ ∂f/∂x₁, ∂f/∂x₂, …, ∂f/∂xn ]

For f(x, y) = x² + y² the partials are ∂f/∂x = 2x and ∂f/∂y = 2y, so ∇f = [2x, 2y].

Why it matters: The gradient points in the direction of steepest increase — the fastest way uphill. Its length tells you how steep the climb is. To reduce the loss we simply go the opposite way: downhill.

Gradient arrows on a bowl

Imagine looking straight down at the bowl f(x, y) = x² + y². At every point the gradient ∇f points away from the center (steepest increase). We move along −∇f (toward the center) to shrink the loss.

3. The update rule — and why the minus sign

This one line is the heartbeat of machine learning.

The rule

new_w = old_w − learning_rate × gradient

In symbols, with learning rate η (often written lr or the Greek letter eta): w ← w − η · ∇f.

Why the minus sign? The gradient points uphill (toward larger loss). We want smaller loss, so we step in the opposite direction — downhill. Subtracting the gradient does exactly that. If instead you added it (gradient ascent), the loss would climb and the model would get worse.

The learning rate η controls the step size: how far we move each iteration in the downhill direction.

Minimize f(x) = x² by gradient descent

Starting from x₀ = 10, the slope is f′(x) = 2x. Each step subtracts η · 2x, sliding x toward 0 (the minimum).

import numpy as np

def f(x):      return x ** 2      # the function we minimize
def grad(x):   return 2 * x       # its derivative (slope)

x = 10.0            # starting point x0
lr = 0.1            # learning rate (step size)

for step in range(25):
    g = grad(x)                   # which way is uphill?
    x = x - lr * g                # step downhill (note the minus sign)
    if step % 5 == 0:
        print(f"step {step:2d}: x={x:8.4f}  f(x)={f(x):8.4f}")

print(f"\nfinal x = {x:.6f}  (true minimum is x = 0)")

Output: x shrinks 10 → 8 → 6.4 → … → ~0, and f(x) falls toward 0. Each step, x is multiplied by (1 − 2·lr) = 0.8, so it decays smoothly to the minimum.

Two variables: minimize f(x, y) = x² + y²

The same loop, but now the gradient is a vector ∇f = [2x, 2y]. We update the whole point at once.

import numpy as np

def f(p):      return p[0]**2 + p[1]**2        # bowl: x^2 + y^2
def grad(p):   return np.array([2*p[0], 2*p[1]])  # gradient [2x, 2y]

p = np.array([8.0, -6.0])   # start at (x, y) = (8, -6)
lr = 0.1

for step in range(25):
    g = grad(p)             # gradient vector (points uphill)
    p = p - lr * g          # step downhill along -gradient
    if step % 5 == 0:
        print(f"step {step:2d}: x={p[0]:7.4f}  y={p[1]:7.4f}  f={f(p):8.4f}")

print(f"\nfinal point = ({p[0]:.5f}, {p[1]:.5f})  (true minimum is (0, 0))")

Both x and y slide toward 0 together, and the loss f heads to 0. This is exactly what happens with millions of weights — just a much longer vector.

4. Learning rate: too big vs. too small

The learning rate is the single most important knob to get right.

The Goldilocks problem

Learning rateWhat happensSymptom
Too smallTiny steps; barely moves each iterationTraining is painfully slow; may never arrive
Just rightSteady, quick descent to the minimumLoss drops smoothly and settles
Too bigOvershoots the bottom, bounces to the other sideLoss oscillates or explodes to ∞ (diverges)
Why it matters: With f(x) = x² and lr = 0.1, each step multiplies x by 0.8 — smooth convergence. But at lr = 1.1 the multiplier is (1 − 2·1.1) = −1.2: x flips sign and grows every step, diverging to ∞. Try changing lr in the code above to see it.

5. The loss surface — walking downhill

Learning is descending a landscape

Picture the loss as a surface: the horizontal directions are the model's weights, and the height is how wrong the model is. Training = a blindfolded walk downhill. You cannot see the whole valley, but at your feet you can feel the slope (the gradient) and always step in the steepest downhill direction.

  • Height of the surface = loss (error)
  • Position on the surface = current weights
  • Slope under your feet = the gradient ∇f
  • Each footstep = one update w ← w − η · ∇f
Why it matters: The loss surface connects everything — the loss function defines the landscape, the gradient tells you which way to step, and optimization is the strategy for walking it efficiently.

6. Batch, Stochastic & Mini-batch

The difference is simply how much data you use to estimate the gradient each step.

Three flavors of gradient descent

VariantData per stepProsCons
Batch GD The entire dataset Accurate, stable gradient Slow / memory-heavy on big data
Stochastic (SGD) One example at a time Fast updates; noise can escape shallow traps Noisy, jittery path to the minimum
Mini-batch A small group (e.g., 32–256) Best of both; hardware-friendly Extra knob: batch size to tune
In practice: almost everyone uses mini-batch GD (people often just call it "SGD"). It balances the smoothness of full batch with the speed of single-example updates.

7. Local vs. global minima

Not all valleys are the deepest

A simple bowl like x² has one bottom — the global minimum. Complex loss surfaces have many dips. A local minimum is lower than its neighbors but not the lowest point overall. Plain gradient descent only feels the slope right at its feet, so it can settle into a local minimum and stop.

The good news: in the very high-dimensional loss surfaces of deep networks, truly bad local minima are rare — most are nearly as good as the global one. The noise of SGD and tricks like momentum and adaptive optimizers help escape shallow traps and keep training moving.

8. Backprop: gradients via the chain rule

Gradient descent needs a gradient. In a neural network, backpropagation is how we get it.

Where do the gradients come from?

A neural network is a long chain of functions: inputs → weighted sums → activations → … → loss. To update a weight we need ∂L/∂w — how the final loss changes when that one weight wiggles. Backpropagation computes this efficiently using the chain rule: multiply the local slopes along the path from the weight to the loss.

∂L/∂w = (∂L/∂ŷ) × (∂ŷ/∂z) × (∂z/∂w)

The error is measured at the output and pushed backward through the layers, splitting the "blame" for the error across every weight. Those blame values are the gradient — and gradient descent then does w ← w − η · ∇L.

The whole pipeline: derivatives give the local slopes, the chain rule stitches them into a gradient, backpropagation computes that gradient for every weight in a neural network, and gradient descent takes the step. Repeat until the loss is small.

Quick recap

  • Derivative — slope of a function at a point
  • Gradient ∇f — vector of partial derivatives; points uphill (steepest increase)
  • Update rule — new_w = old_w − lr × gradient (minus = go downhill)
  • Learning rate — step size; too big diverges, too small crawls
  • Variants — batch (all data), SGD (one example), mini-batch (a small group)
  • Backpropagation — the chain rule computing gradients for every weight
