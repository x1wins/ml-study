📊 Evaluation Metrics: Measuring If Your Model Actually Works

1. Why Accuracy Alone Is Misleading

Accuracy is the first metric everyone learns — and the one that fools the most people.

What accuracy measures

Accuracy is simply the fraction of predictions the model got right.

accuracy = (correct predictions) ÷ (total predictions)

That sounds perfect — until the classes are imbalanced.

The class-imbalance trap

Imagine a fraud detector where only 1 in 1000 transactions is fraud. A lazy model that predicts "not fraud" for everything is:

999 correct ÷ 1000 total = 99.9% accuracy

99.9% accuracy — and it catches zero fraud. It is completely useless, yet accuracy calls it excellent.

Why it matters: When one class is rare (fraud, disease, defects), accuracy rewards ignoring it. You need metrics that focus on the rare, important class — that is what precision and recall do.

2. The Confusion Matrix

Every classification metric is built from four counts. Learn these once and everything else follows.

The four outcomes

For a binary problem (positive = the thing we care about, e.g. "fraud"), each prediction lands in one of four buckets:

  • TP (True Positive) — predicted positive, and it really was positive ✓
  • FP (False Positive) — predicted positive, but it was actually negative (false alarm)
  • FN (False Negative) — predicted negative, but it was actually positive (a miss)
  • TN (True Negative) — predicted negative, and it really was negative ✓
Read it like this: the diagonal (TP, TN) is where the model was right; the off-diagonal (FP, FN) is where it was wrong. Which mistake hurts more — a false alarm or a miss — decides which metric you optimize.

Accuracy rewritten from the four counts

accuracy = (TP + TN) ÷ (TP + TN + FP + FN)

Notice accuracy lumps all correct answers together. If TN is huge (many easy negatives), it drowns out how badly the model handles the rare positives.

3. Precision, Recall & F1

The two metrics that actually describe how a model handles the class you care about — plus the number that balances them.

Precision — "when I say positive, how often am I right?"

precision = TP ÷ (TP + FP)

Precision punishes false alarms. High precision means few of your positive predictions are wrong. Care about this when a false positive is expensive (e.g., flagging a good customer's card as fraud and blocking it).

Recall — "of all the real positives, how many did I catch?"

recall = TP ÷ (TP + FN)

Recall punishes misses. High recall means you find most of the true positives. Care about this when a false negative is dangerous (e.g., missing a real disease or real fraud).

F1 — one number balancing both

F1 is the harmonic mean of precision and recall. The harmonic mean stays low unless both are high, so you can't game it by maximizing just one.

F1 = 2 · (precision · recall) ÷ (precision + recall)
Why harmonic (not plain) mean? If precision = 1.0 but recall = 0.0, the plain average is 0.5 (looks okay). The harmonic mean is 0.0 — correctly telling you the model is broken.

Worked example (with real numbers)

Say a fraud model is evaluated on 1000 transactions. The confusion matrix comes out as:

 Predicted FraudPredicted Legit
Actually FraudTP = 40FN = 10
Actually LegitFP = 30TN = 920

Plug the counts in:

precision = 40 ÷ (40 + 30) = 40 ÷ 70 ≈ 0.571
recall = 40 ÷ (40 + 10) = 40 ÷ 50 = 0.800
F1 = 2 · (0.571 · 0.800) ÷ (0.571 + 0.800) ≈ 0.667

Meanwhile accuracy = (40 + 920) ÷ 1000 = 0.960. Accuracy looks excellent, but precision tells us 43% of our fraud alerts are false alarms — a very different story.

Takeaway: report precision, recall and F1 together for imbalanced problems. A single accuracy number hides the mistakes that matter.

4. The Precision/Recall Tradeoff & Thresholds

You rarely get high precision and high recall for free — pushing one usually lowers the other.

The decision threshold

Most classifiers don't output a hard yes/no — they output a probability (e.g., 0.73 chance of fraud). You turn that into a decision by comparing it to a threshold, usually 0.5:

predict positive if probability ≥ threshold

Moving the threshold changes the counts, and therefore precision and recall:

  • Raise the threshold (e.g., 0.9) → only very confident positives pass → fewer false alarms → precision up, but you miss more → recall down.
  • Lower the threshold (e.g., 0.2) → you flag almost anything suspicious → you catch more real positives → recall up, but more false alarms → precision down.
Why it matters: the "best" threshold depends on the cost of each mistake. A cancer screen wants high recall (never miss a case, tolerate false alarms). A spam filter wants high precision (never trash a real email, tolerate a little spam getting through).

5. ROC Curve & AUC

A way to judge a classifier across every possible threshold at once.

The ROC curve

Instead of picking one threshold, the ROC curve sweeps through all of them and plots two rates against each other:

  • True Positive Rate (recall) = TP ÷ (TP + FN) — on the y-axis
  • False Positive Rate = FP ÷ (FP + TN) — on the x-axis
Intuition: a perfect model hugs the top-left corner (catches all positives with no false alarms). The diagonal is random guessing. The more the curve bows up toward the corner, the better.

AUC — Area Under the Curve

AUC collapses the whole ROC curve into a single number: the area beneath it, from 0 to 1.

AUCMeaning
1.0Perfect classifier
0.9 – 1.0Excellent
0.7 – 0.9Good / acceptable
0.5No better than a coin flip
< 0.5Worse than random (predictions are backwards)

A neat interpretation: AUC is the probability that the model ranks a random positive example higher than a random negative one. It is threshold-independent, which makes it great for comparing models — but you still choose a threshold for real-world use.

6. Regression Metrics

When the model predicts a number (price, temperature, age) instead of a class, you measure how far off it is.

MAE — Mean Absolute Error

The average size of the error, ignoring direction. In the same units as the target.

MAE = (1 ÷ n) · Σ |yi − ŷi|

Easy to interpret ("off by $3.20 on average") and robust to outliers because it doesn't square the errors.

MSE — Mean Squared Error

The average of the squared errors. Squaring punishes big mistakes much more than small ones.

MSE = (1 ÷ n) · Σ (yi − ŷi)2

Units are squared (e.g., dollars²), which is hard to interpret — but MSE is smooth and differentiable, so it's a favorite training loss.

RMSE — Root Mean Squared Error

Just the square root of MSE, bringing the number back to the original units.

RMSE = √( (1 ÷ n) · Σ (yi − ŷi)2 )
MAE vs RMSE: both are in target units. RMSE is always ≥ MAE and grows when errors are uneven — so if RMSE is much larger than MAE, you have a few big outlier errors.

R² — Coefficient of Determination

How much of the variance in the target your model explains, compared to just predicting the mean every time.

R² = 1 − ( Σ(yi − ŷi)2 ÷ Σ(yi − ̄y)2 )
  • R² = 1 — perfect predictions
  • R² = 0 — no better than always guessing the mean
  • R² < 0 — worse than guessing the mean (a genuinely bad model)

R² is unitless, so it's handy for a quick "how good, roughly?" — but pair it with RMSE or MAE to know the error in real units.

7. Which Metric to Use When

Quick decision table

SituationUse this metricWhy
Balanced classes, all errors equal Accuracy Simple and meaningful when classes are roughly equal
Missing a positive is costly (disease, fraud) Recall Minimizes false negatives — catch as many real cases as possible
A false alarm is costly (spam filter, blocking users) Precision Minimizes false positives — be right when you flag something
Imbalanced classes, need one balanced number F1 Balances precision and recall; not fooled by a huge negative class
Comparing models across all thresholds ROC-AUC Threshold-independent ranking quality
Regression, interpretable error, robust to outliers MAE Average error in real units, outliers don't dominate
Regression, want to penalize large errors MSE / RMSE Squaring makes big misses hurt more
Regression, "how much variance explained?" R² Unitless summary vs. a mean baseline
Rule of thumb: start by asking "which mistake is worse for my problem?" The answer picks your metric. Never rely on accuracy alone for imbalanced data.

8. Runnable Code

Precision, recall & F1 from TP / FP / FN (numpy)

Short and correct — runs with just numpy. Uses the worked-example counts from section 3.

import numpy as np

def precision_recall_f1(tp, fp, fn):
    # guard against divide-by-zero
    precision = tp / (tp + fp) if (tp + fp) > 0 else 0.0
    recall    = tp / (tp + fn) if (tp + fn) > 0 else 0.0
    if (precision + recall) > 0:
        f1 = 2 * precision * recall / (precision + recall)
    else:
        f1 = 0.0
    return precision, recall, f1

# counts from the worked example
tp, fp, fn = 40, 30, 10
p, r, f1 = precision_recall_f1(tp, fp, fn)

print(f"precision = {p:.3f}")   # 0.571
print(f"recall    = {r:.3f}")   # 0.800
print(f"F1        = {f1:.3f}")  # 0.667

Bonus: deriving the same counts straight from prediction arrays with numpy.

import numpy as np

y_true = np.array([1, 1, 0, 0, 1, 0, 1, 0])  # ground truth (1 = positive)
y_pred = np.array([1, 0, 0, 1, 1, 0, 1, 0])  # model predictions

tp = int(np.sum((y_pred == 1) & (y_true == 1)))  # 3
fp = int(np.sum((y_pred == 1) & (y_true == 0)))  # 1
fn = int(np.sum((y_pred == 0) & (y_true == 1)))  # 1

p, r, f1 = precision_recall_f1(tp, fp, fn)
print(tp, fp, fn)               # 3 1 1
print(f"{p:.3f} {r:.3f} {f1:.3f}")  # 0.750 0.750 0.750
Tip: in real projects, sklearn.metrics gives precision_score, recall_score, f1_score, roc_auc_score, and confusion_matrix out of the box — but writing them once by hand makes the formulas stick.
