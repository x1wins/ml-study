🤖 Transformers & Attention

Self-attention, Query/Key/Value, multi-head attention, and positional encoding — the architecture behind every modern LLM, explained simply.

Big picture: A transformer looks at a whole sequence at once and lets every token decide which other tokens to "pay attention to." No recurrence, no waiting for the previous step — just parallel math. That single idea (attention) is what powers ChatGPT, translation, and image models.

1. Why Transformers? (vs RNNs)

RNNs and LSTMs read a sequence one step at a time. Transformers read it all at once.

The two problems transformers solve

RNNs process tokens sequentially: to understand word 100 they must first pass through words 1…99. This causes two pain points:

  • No parallelism — each step waits for the previous one, so training is slow on modern GPUs.
  • Long-range dependencies fade — information from far-back words gets diluted step after step (the vanishing-gradient problem).

A transformer fixes both: it compares every token to every other token directly and in parallel. The distance between two words no longer matters — word 1 and word 1000 are one attention step apart.

Why it matters: Parallel processing + direct long-range connections is exactly what lets us train enormous models on enormous text — the recipe behind today's LLMs.

RNN vs Transformer at a glance

 RNN / LSTMTransformer
Processing orderOne step at a timeWhole sequence at once
Parallel on GPU?No (sequential)Yes
Long-range linksWeaken with distanceDirect, distance-independent
Word orderBuilt in (via recurrence)Added via positional encoding

2. Self-Attention: Query, Key, Value

Every token asks a question, offers a label, and carries content — Q, K, V.

The library analogy

Attention is like searching a library. Each token produces three vectors from its embedding (via three learned weight matrices):

  • Query (Q) — "what am I looking for?" (your search request)
  • Key (K) — "what do I offer?" (the label on each book)
  • Value (V) — "here is my actual content" (the book itself)

A token compares its Query against every token's Key. Good matches get high scores. Those scores become weights, and the token pulls in a weighted blend of everyone's Value. Result: each token's new representation is informed by exactly the other tokens that matter to it.

Q = XWQ  ·  K = XWK  ·  V = XWV
Key idea: "self"-attention means Q, K and V all come from the same sequence — the sentence is looking at itself to figure out which words explain which.

3. The Attention Formula

Scaled dot-product attention

Attention(Q, K, V) = softmax( QKᵀ ∕ √dk ) V

Read left to right, in plain words:

  • QKᵀ — dot every Query with every Key. A large dot product means the two vectors point the same way → "these tokens are relevant to each other."
  • ∕ √dk — divide by the square root of the key dimension. Without this, big vectors make the scores huge, and softmax would become razor-sharp (one token grabs everything). Scaling keeps gradients healthy.
  • softmax(…) — turn the raw scores into positive weights that sum to 1 (a probability distribution over "how much to attend to each token").
  • × V — use those weights to take a weighted average of the Value vectors. That blend is the token's new, context-aware representation.
Why divide by √dk? If keys have dimension dk, the dot products grow roughly like dk. Dividing by √dk keeps the numbers in a stable range so softmax doesn't saturate and stop learning.

4. Why Softmax? (Euler's e & probabilities)

Softmax turns any list of scores into a clean probability distribution.

The softmax function

softmax(xi) = exi ∕ Σj exj

Each score is passed through ex (the exponential, built on Euler's number e ≈ 2.71828), then normalized so the whole set sums to 1. Two properties make this perfect for attention:

  • Always positive — ex is never negative, so every attention weight is a valid, non-negative "amount of focus."
  • Amplifies differences — because ex grows fast, a slightly higher score gets a disproportionately larger share. Attention can decisively favor the most relevant tokens while still spreading a little weight elsewhere.

The result is a probability distribution: a set of weights between 0 and 1 that add up to exactly 1 — literally "what fraction of my attention goes to each token."

Why e specifically? Using ex makes the math differentiable and the gradient beautifully simple — the same reason cross-entropy + softmax pair so cleanly in classification. That smoothness is what gradient descent needs to learn.

5. Multi-Head Attention

Run attention several times in parallel, each head learning a different kind of relationship.

Many perspectives at once

A single attention operation can only capture one "type" of relationship. Instead, transformers split the vectors into several smaller heads and run attention in each independently. One head might track grammatical subject–verb links, another might follow pronoun references, another local phrasing.

MultiHead = Concat(head1, …, headh) WO

Each head computes its own scaled dot-product attention on its slice of Q, K, V. The outputs are concatenated back together and passed through a final weight matrix WO.

Why it matters: Multiple heads let the model attend to different things simultaneously — like reading a sentence for grammar, meaning, and tone all at once.

6. Positional Encoding

Attention has no built-in sense of order, so we inject position into the inputs.

Giving the model a sense of order

Because a transformer looks at all tokens at once, "the cat sat" and "sat the cat" would look identical to raw attention — it sees a set, not a sequence. To fix this we add a positional encoding vector to each token's embedding, encoding where it sits in the sequence.

The original transformer uses sine and cosine waves of different frequencies, so each position gets a unique, smooth signature:

PE(pos, 2i) = sin( pos ∕ 100002i∕d )  ·  PE(pos, 2i+1) = cos( pos ∕ 100002i∕d )
Why sine/cosine? Smooth periodic patterns let the model generalize to positions (and sequence lengths) it never saw during training, and make relative distances easy to compute. Modern LLMs often use learned or rotary (RoPE) encodings, but the goal is the same: tell the model the order of the tokens.

7. Encoder/Decoder vs Decoder-Only (LLMs)

The same attention block, arranged differently for different jobs.

Three flavors of transformer

TypeStructureBest atExample
Encoder–Decoder Encoder reads input, decoder writes output Translation, summarization (seq → seq) Original Transformer, T5
Encoder-only Reads the whole input at once (bidirectional) Understanding, classification, embeddings BERT
Decoder-only Predicts the next token, left to right (masked) Text generation, chat GPT, Llama, most LLMs

Modern chat LLMs are almost all decoder-only: they use masked self-attention so each token can only attend to tokens before it, then predict the next token — over and over — to generate text.

Why transformers power modern LLMs: they scale. Because attention is parallel and captures long-range meaning, you can pour in more data, more parameters, and more compute and keep getting better — the "scaling laws" that took us from a research paper to ChatGPT.

8. Self-Attention in numpy

Scaled dot-product attention, from scratch

The whole formula in a few lines — correct and runnable.

import numpy as np

def softmax(x, axis=-1):
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))  # stability shift
    return e / e.sum(axis=axis, keepdims=True)

def attention(Q, K, V):
    # Q, K, V shapes: (seq_len, d_k)
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)   # QKᵀ / √d_k   -> (seq, seq)
    weights = softmax(scores, axis=-1)  # rows sum to 1
    return weights @ V, weights         # weighted sum of Values

# Toy example: 3 tokens, each a 4-dim vector
np.random.seed(0)
X = np.random.randn(3, 4)

# Learned projection matrices (random here for illustration)
Wq = np.random.randn(4, 4)
Wk = np.random.randn(4, 4)
Wv = np.random.randn(4, 4)

Q, K, V = X @ Wq, X @ Wk, X @ Wv
out, attn = attention(Q, K, V)

print("attention weights (each row sums to 1):")
print(np.round(attn, 3))
print("output shape:", out.shape)   # (3, 4): one context vector per token
That's the core of a transformer. Stack this (with multi-head splitting, a feed-forward layer, residual connections and layer-norm) dozens of times, add positional encoding at the input, and you have the engine behind modern LLMs.
