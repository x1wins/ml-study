🖼️ Convolutional Neural Networks (CNNs)

How computers "see" — convolution, filters, feature maps, and pooling, explained simply with worked examples and diagrams.

← Back to Learning Path
Big picture: A regular neural network treats an image as a flat list of pixels and misses the fact that nearby pixels form shapes. A CNN slides small filters across the image to detect edges, textures, and eventually whole objects — reusing the same weights everywhere. That reuse is what makes vision practical.

1. Why images need CNNs

A 200×200 color image is 120,000 numbers. Connecting every pixel to every neuron explodes fast.

The problem with fully-connected networks on images

Imagine feeding a 200×200×3 image into a dense layer of 1,000 neurons. That's 120,000 inputs × 1,000 neurons = 120 million weights in the first layer alone. Worse, a dense layer treats pixel (0,0) and pixel (199,199) as unrelated — it has no idea they might be part of the same edge.

CNNs fix this with two big ideas:

  • Locality — a pixel is most related to its neighbors, so look at small patches at a time (e.g., 3×3), not the whole image at once.
  • Parameter sharing — the same small filter slides across the whole image. If a filter learns to detect a vertical edge, it can find that edge anywhere, using just 9 weights instead of millions.
Why it matters: parameter sharing cuts weights from millions to a few hundred, and gives translation invariance — a cat is a cat whether it's top-left or bottom-right of the picture.

2. The Convolution Operation

Slide a small grid of weights (the kernel) over the image, multiply-and-add at each position.

What convolution does, step by step

Place the kernel over a patch of the input, multiply each overlapping pair, sum them into a single number, then slide the kernel one step and repeat. That single number is one pixel of the output feature map.

output(i,j) = Σm Σn input(i+m, j+n) · kernel(m,n)

A worked example (numbers you can check by hand)

Take a 3×3 patch of the input and a 3×3 kernel. Multiply matching cells, then add them all up:

Input patch Kernel Element-wise product
1 0 2
4 1 0
0 2 3		 1 0 −1
1 0 −1
1 0 −1		 1 0 −2
4 0 0
0 0 −3
sum = 1 + 0 − 2 + 4 + 0 + 0 + 0 + 0 − 3 = 0

That single value (0) becomes one pixel of the feature map. This particular kernel is a vertical-edge detector: it responds strongly where the left side is bright and the right side is dark.

3. Filters, Kernels & Feature Maps

A filter is just a small grid of learnable weights. Its output is a feature map.

Key vocabulary

  • Kernel / filter — a small weight grid (often 3×3 or 5×5). "Kernel" usually means the 2D weight grid; "filter" often means the full stack across all input channels. In practice the words are used interchangeably.
  • Feature map (activation map) — the 2D output produced by sliding one filter over the input. Bright spots = "this feature was found here".
  • Channels — a color image has 3 input channels (R, G, B). A conv layer with 32 filters produces 32 output channels.
Why it matters: the filter weights are learned by backpropagation, not hand-designed. Early layers learn edges and colors; deeper layers combine those into textures, parts, and eventually whole objects.

4. Stride & Padding

Two knobs that control how the kernel moves and how big the output is.

Stride

Stride is how many pixels the kernel jumps each step. Stride 1 moves one pixel at a time (dense output). Stride 2 skips every other position, roughly halving the output size and reducing computation.

Padding

Padding adds a border of zeros around the input so the kernel can sit on the edges. Without it, the output shrinks with every conv layer and edge pixels get under-used.

  • "valid" padding — no padding; output is smaller than input.
  • "same" padding — pad so the output matches the input size.

Output size formula

out = ⌊(N − K + 2P) / S⌋ + 1

where N = input size, K = kernel size, P = padding, S = stride. Example: a 5×5 input, 3×3 kernel, no padding, stride 1 → (5 − 3 + 0)/1 + 1 = 3 → a 3×3 output.

5. Pooling

Downsample feature maps to keep the strongest signals and shrink the data.

Max pooling vs. average pooling

Pooling slides a small window (usually 2×2, stride 2) over a feature map and summarizes each window into one number. Max pooling keeps the largest value (the strongest activation); average pooling takes the mean.

Why pool? It shrinks the data (less compute), keeps the strongest features, and adds a bit of position-invariance — the network cares that an edge exists nearby, not its exact pixel. Max pooling is the most common choice.

6. Typical CNN Architecture

Stack conv + activation + pool blocks to extract features, then flatten into a classifier.

The classic pipeline

A CNN alternates convolution (find features), ReLU (add non-linearity), and pooling (shrink), repeating to build up from simple edges to complex objects. The final feature maps are flattened and passed to fully-connected layers that make the final decision.

Intuition: the conv/pool stack is a feature extractor that turns raw pixels into a compact description ("has whiskers, pointy ears, fur texture"). The fully-connected head is a plain neural network that reads that description and picks a class.

A tiny 2D convolution in numpy

Valid convolution (no padding, stride 1) of a single-channel image with one kernel:

import numpy as np

def conv2d(image, kernel):
    """Valid 2D convolution: no padding, stride 1."""
    kh, kw = kernel.shape
    ih, iw = image.shape
    oh, ow = ih - kh + 1, iw - kw + 1        # output size formula (P=0, S=1)
    out = np.zeros((oh, ow))

    for i in range(oh):
        for j in range(ow):
            patch = image[i:i+kh, j:j+kw]    # slide the window
            out[i, j] = np.sum(patch * kernel)  # multiply-and-add
    return out

image = np.array([[1, 0, 2, 1, 0],
                  [4, 1, 0, 2, 1],
                  [0, 2, 3, 0, 1],
                  [1, 1, 0, 2, 2],
                  [2, 0, 1, 1, 0]], dtype=float)

# vertical-edge detector: bright on the left, dark on the right
kernel = np.array([[ 1, 0, -1],
                   [ 1, 0, -1],
                   [ 1, 0, -1]], dtype=float)

feature_map = conv2d(image, kernel)
print(feature_map.shape)   # (3, 3)
print(feature_map)

Real frameworks vectorize this (and add channels, padding, and stride), but the core loop is exactly this: slide, multiply, sum.

7. Use Cases

Where CNNs shine

TaskExample
Image classificationIs this a cat, dog, or car?
Object detectionDraw boxes around every pedestrian (self-driving cars)
SegmentationLabel every pixel (medical scans, satellite imagery)
Face recognitionUnlocking your phone
Beyond imagesAudio spectrograms, 1D signals, even some text tasks
Takeaway: anywhere the data has a grid structure with local patterns (images being the classic case), CNNs are a strong, efficient default.

Quick recap

  • Convolution — slide a small kernel, multiply-and-add to make a feature map
  • Parameter sharing — same filter everywhere → far fewer weights + translation invariance
  • Stride & padding — control step size and output dimensions
  • Pooling — downsample, keep the strongest signals
  • Architecture — conv → ReLU → pool … → flatten → fully-connected → softmax
